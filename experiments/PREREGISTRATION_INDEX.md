# Pre-registration index

A plan file was written before each confirmatory run. It fixes the datasets or tasks, the seed rule, the number of trials, the pass criterion, and the analysis script. Each run also has a manifest in `out/` listing the SHA-256 of every script it executed; from MINI-39 on, the manifest also lists the SHA-256 of the plan file.

The plan files are internal working documents in Indonesian. The plans are not part of this release and are available to the editor and reviewers on request. The SHA-256 in the fourth column fixes the content of each plan, so a copy provided on request can be checked with `sha256sum`. The time in the third column is the time recorded inside the plan. The plans are not entries in a third-party registry.

`python verify_manifests.py` checks every manifest against the released scripts (see the README, *Provenance notes*). Each run follows the seed rule stated in its plan, so it can be re-executed and compared bit for bit with the per-trial outputs in `out/`.

**Notes**

1. Comments, docstrings, and printed messages of some scripts and of two plans (MINI-25, MINI-26) were edited after the runs; the manifests keep the run-time hashes. `verify_manifests.py` resolves each entry to the current file, to the exact run-time copy in `frozen/`, or, for the few run-time copies whose comments hold internal working notes, to the SHA-256 of the program structure in `frozen/WITHHELD.tsv`. Two run-time scripts differ from the released ones in code: `pkg/src/bridge_gate/cli.py` renames the function `run_paper` to `run_reference` (no effect on decisions), and `analisis_mini39.py` reads an empty `error` column as text instead of as missing values; without this fix every row was filtered out. The MINI-39 fix was recorded as a deviation in the run report at the time.
2. MINI-23 has no separate manifest. MINI-24 recomputed every MINI-23 column with identical seeds, added the tests on the final configuration, and is the run reported in the paper.
3. The development runs MINI-17 and MINI-19 recorded earlier versions of `mini17_trainsize.py` and `mini19_fs_lebar.py`. Before the confirmatory runs MINI-20 and MINI-21, only the seed offset and the number of trials changed; the confirmatory manifests list the hashes of those versions (kept in `frozen/`). The earlier versions were not retained, so two entries of `out/mini17_MANIFEST.sha256` and `out/mini19_MANIFEST.sha256` cannot be checked.
4. MINI-47b re-ran the five small datasets of collection (A) that MINI-47 skipped by design; its plan is the addendum recorded after MINI-47 and before MINI-47b.
5. The manifests of the E2 amendment and of the Volkert supplement also list the two dataset-screening scripts `screen_e2_external.py` and `screen_e2_openml_custom.py`, which `setting_e2.py` imports to load the data. Both were edited after these two runs, and the run-time versions were not retained; the E2 manifest itself does not list them. `verify_manifests.py` reports the two entries as documented exceptions.
